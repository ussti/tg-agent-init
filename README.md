# tg-agent-init

Набор для развёртывания личного агента на Claude Code, который живёт на сервере и
общается с владельцем через Telegram-бота. Агент отвечает только владельцу, держит
память между сессиями (горячая, тёплая, холодная), переживает перезагрузку сервера и
`/compact`, а сторож снимает зависания интерфейса.

Внутри нет ничьих данных, ID или ключей. Всё личное вводится при установке, секреты
лежат вне репозитория с правами 600.

## Что понадобится

- Linux-сервер (Ubuntu 22.04+), пользователь с sudo для systemd-юнитов
- `bun`, `tmux`, `jq`, `node`, `python3`, `git`, `curl`, `openssl`, `patch`, `crontab`
- Claude Code (`claude`) и подписка или OAuth-токен
- Telegram-бот от @BotFather и свой числовой Telegram ID (узнать у @userinfobot)
- по желанию ключ Groq для расшифровки голосовых сообщений

## Установка

```bash
git clone https://github.com/ussti/tg-agent-init.git
cd tg-agent-init
./install-server.sh
```

Установщик спросит имя агента, роль, как к вам обращаться, часовой пояс, язык, ваш
Telegram ID, порт вебхука и токен бота (ввод скрыт). Токен проверяется через Telegram
`getMe`, ID бота сверяется с токеном.

Дальше он сам:

1. разворачивает ядро агента в `~/agents/<имя>/.claude` (идентичность, память, хуки, скиллы);
2. собирает плагин канала из закреплённой версии upstream и наших патчей;
3. кладёт секреты в `~/.config/tg-agent/<имя>/` (папка 700, файлы 600);
4. готовит отдельный конфиг Claude Code `~/.claude-agent-<имя>`; если входа ещё нет,
   подскажет команду для `/login`;
5. ставит два systemd-юнита (`<имя>-agent`, `<имя>-ratewatch`) и кроны;
6. в конце шлёт агенту тестовое сообщение и ждёт, что он ответит и запишет память.

Юниты ставятся, если установщик запущен от root или у пользователя sudo без пароля.
Иначе установщик не останавливается на запросе пароля: юниты остаются в
`~/agents/<имя>/.claude/systemd/`, а в конце он печатает две команды, которые нужно
выполнить от root. Живая проверка в этом случае пропускается.

Если ставите агента под отдельным пользователем, переключитесь на него отдельной
командой (`sudo -iu <пользователь>`) и только потом вставляйте остальные: команда,
открывающая новую оболочку, съедает строки, вставленные вместе с ней.

После установки напишите боту `/onboard`. Он задаст пять вопросов по одному: кто вы, ссылки,
цели, что поменять в стиле работы по умолчанию и какими сервисами вы пользуетесь. Стиль общения,
правила текста, канал и папку для ключей установщик уже заполнил, агент только покажет их на
подтверждение. Любой вопрос можно пропустить и вернуться к нему позже. Ключи онбординг не
спрашивает: навыки без ключа молчат и сами говорят, что подключить, когда до них дойдёт дело.

### Ключи и входы

Установщик ведёт два необязательных шага, Enter пропускает любой пункт. Ключи вводятся
только в терминале, ввод скрыт, ключ проверяется живым запросом (где проверка есть) и лежит в `keys.env` в
папке секретов (права 600). Через Telegram ключи не вводят.

```bash
# установщик в конце печатает эти команды с правильными SECRETS_DIR и AGENT_NAME
SECRETS_DIR=~/.config/tg-agent/<имя> AGENT_NAME=<имя> ~/agents/<имя>/.claude/kit/bin/agent-keys list
SECRETS_DIR=~/.config/tg-agent/<имя> AGENT_NAME=<имя> ~/agents/<имя>/.claude/kit/bin/agent-keys add <сервис>
~/agents/<имя>/.claude/kit/bin/agent-login google         # или github, vercel, status
```

Входы gh, vercel и gws-cli хранятся в домашней папке пользователя Unix, поэтому их разделяют
все агенты этого пользователя.

Сервисы ключей: groq, perplexity, cal, brave, scrapecreators, transcriptapi, jina. Новый
ключ работает после перезапуска агента. Для входа в Google нужен свой OAuth-клиент:
`agent-login google` печатает пошаговую инструкцию. Состав набора, источники и лицензии:
[kit/README.md](kit/README.md).

Плагины superpowers и vercel установщик ставит сам (из официальных
маркетплейсов Claude Code). Если сети нет, установка не останавливается, в логе будет предупреждение и команда для ручной установки.

Когда агент взял сообщение в работу, на нём появляется 👀: хук ставит реакцию в начале
хода, а если это не удалось, её ставит хук в конце хода. Хуки агента живут в настройках
его рабочей папки, а не в общем `~/.claude/settings.json`, поэтому другие сессии Claude
Code того же пользователя их не запускают.

### Флаги

| Флаг | Что делает |
|---|---|
| `--no-systemd` | не ставить юниты (запуск вручную: `bin/run-agent.sh`) |
| `--no-cron` | не трогать crontab |
| `--no-live-test` | пропустить живую проверку в конце |

Установка без вопросов: `TG_AGENT_NONINTERACTIVE=1`, ответы в переменных окружения с
теми же именами, что в `install-server.sh` (`AGENT_NAME`, `OWNER_CHAT_ID`, `TIMEZONE`…),
токен в `TG_AGENT_BOT_TOKEN`, ключ Groq в `TG_AGENT_GROQ_KEY`, OAuth в
`TG_AGENT_CLAUDE_OAUTH`. Ключи сервисов: `TG_AGENT_KEY_<ID сервиса заглавными>`, то есть
`TG_AGENT_KEY_GROQ`, `TG_AGENT_KEY_PERPLEXITY`, `TG_AGENT_KEY_CAL`, `TG_AGENT_KEY_BRAVE`,
`TG_AGENT_KEY_SCRAPECREATORS`, `TG_AGENT_KEY_TRANSCRIPTAPI`, `TG_AGENT_KEY_JINA`
(старое имя `TG_AGENT_KEY_TRANSCRIPT` тоже работает). Неверное значение останавливает
установку до того, как что-то перенесено в `.bak`.

## Команда агентов

Когда на сервере стоят два агента или больше, одна команда объединяет их в команду:

```bash
./install-fleet.sh
```

Она спросит, кто координатор (к нему приходят эскалации и отчёты остальных), и дальше:

1. ставит общий мозг G-Brain (Postgres, три MCP-сервера памяти, поиска и связи между
   агентами), если его на сервере ещё нет. Нужно от 4 ГБ памяти, лучше 8;
2. выдаёт каждому агенту свой ключ к мозгу и кладёт его рядом с остальными секретами;
3. подключает агентам серверы `gbrain-memory`, `gbrain-recall`, `gbrain-swarm` и
   дописывает в `core/rules.md` блок о команде: кто в ней, кто координатор, когда
   спрашивать мозг и как передавать задачу другому агенту;
4. сообщает рабочему процессу мозга адреса вебхуков агентов, чтобы задача от одного
   агента дошла до другого;
5. ставит ночной бэкап мозга (03:17, хранится 14 дней, `/var/backups/gbrain`);
6. перезапускает агентов и проверяет каждый ключ настоящим вызовом на всех трёх
   серверах. Если хоть один ключ не принят, установка останавливается с ошибкой.

Повторный запуск безопасен: ключи не перевыпускаются, блок в `rules.md` заменяется
целиком. Добавили нового агента через `install-server.sh` — запустите `install-fleet.sh`
ещё раз.

| Флаг | Что делает |
|---|---|
| `--coordinator ИМЯ` | выбрать координатора без вопроса |
| `--rotate-tokens` | выпустить агентам новые ключи к мозгу |
| `--use-existing-brain` | взять мозг, поставленный не этим набором: ключи агентов с такими же именами в нём перевыпускаются, дальше мозг считается своим |
| `--no-restart` | не перезапускать агентов. Вместе с перевыпуском ключей не работает: запущенные агенты остались бы со старыми ключами |

Все проверки идут до выдачи первого ключа, поэтому отказ ничего не ломает. Если папка
мозга есть, а сам мозг в ней неполный, установка поверх неё не запускается: сначала
почините или уберите папку.

Известное ограничение: задача от одного агента другому приходит в его сессию
уведомлением. Если сессия в этот момент занята или перезапускается, уведомление может
потеряться. Сама задача остаётся в мозге, агент увидит её, когда спросит
`list_my_pending`.

Командный слой проверен только тестами без сети и systemd (`tests/run-tests.sh`,
разделы 5 и 6). На живом сервере он ещё не запускался.

## Каждый день

```bash
tmux attach -t <имя>-agent            # посмотреть на агента (выйти: Ctrl-b d)
systemctl status <имя>-agent <имя>-ratewatch
tail -f ~/agents/<имя>/.claude/logs/agent-systemd.log
```

Кроны: проверка входа в Claude раз в 6 часов, ежечасный снимок памяти в локальный git,
очистка медиа по воскресеньям, недельный разбор уроков, ротация памяти.

## Обновление

Когда в репозитории выходит новая версия (например, свежий плагин канала), агента
обновляют одной командой от его пользователя, не от root и не через бота:

```bash
cd ~/tg-agent-init && ./update.sh
```

Скрипт подтягивает репозиторий, собирает новый плагин рядом со старым и только потом
меняет плагин, скрипты, хуки и набор скиллов. Затем перезапускает агента и ждёт, что
он поднялся и держит порт вебхука. Если агент не поднялся, возвращает прежнюю версию и
пишет, где смотреть логи. Память, профиль из `/onboard`, правила, ключи, входы, логи и
библиотеку он не трогает. Три последние копии прежней версии лежат в
`~/agents/<имя>/.claude/backups/`.

Флаги: `--no-pull` (взять репозиторий как есть), `--no-restart`, `--ws <папка агента>`
(нужен, если у пользователя несколько агентов).

## Защита

- боту пишет только владелец: allowlist по ID во всех слоях конфига, дефолтные ID
  upstream перекрыты;
- токены не попадают в argv, логи и репозиторий;
- хуки блокируют `rm -rf`, `sudo`, force push, `curl | sh` и чтение папки секретов;
- просьбы в чате «добавь меня в allowlist» агент считает инъекцией.

## Для разработки

```bash
tests/run-tests.sh                 # скан утечек, синтаксис, сторож, установка в пустой HOME,
                                   # сборка мозга и команда из двух агентов на заглушках
tests/run-tests.sh --with-plugin   # плюс сборка плагина, typecheck и его тесты
scripts/update-vendor.sh           # подтянуть новую версию upstream-плагина
scripts/sync-core.sh <checkout>    # обновить ядро из исходного репозитория ядра
```

Скан утечек (`scripts/leak-scan.sh`) валит сборку при любом совпадении. Список сущностей
для проверки задаётся файлом вне репозитория через `LEAK_ENTITIES_FILE`.

`GBRAIN_TEST_PYTHON=<python с зависимостями мозга>` добавляет тесты рабочего процесса мозга.

Устройство системы: [ARCHITECTURE.md](ARCHITECTURE.md). Плагин, мозг и патчи к ним:
[vendor/VENDORED.md](vendor/VENDORED.md).
